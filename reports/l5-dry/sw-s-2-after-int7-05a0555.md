## Прогон 1 — `sw-s-2-after-int7-05a0555-run1.md`: FAIL по ошибке судьи, не Kadr

| Что | Замер |
|---|---|
| До перезагрузки | «N из 225 МБ» 0 → 75, 37 значений, без отката, молчание 0 с |
| После перезагрузки | 0 → 158, 77 значений, без отката, самое долгое молчание 25 с |
| Субтитры | через 163 с, 59 строк |
| Хранилище частей | cache: «speech download ru: first byte 177 ms, first part written 30 ms, store cache, quota 20616 MB used 260 MB, persisted no» |
| Ошибки страницы, тосты ошибок | 0, 0 |

Почему «✗ с сохранённого: 0 МБ после 75 МБ» — ошибка судьи, а не Kadr:

- Судья ждал, что после перезагрузки счётчик продолжит с 75. Но Kadr пишет «N из M», где M — только то, чего не хватает:
  - `captions.ts`: `missing = await missingBytes(…)`, `mb = round(missing / 1e6)`, `fraction = fetched / missing`;
  - `ToolSheets.tsx:238`: `done = round(fraction × mb)`.
- Поэтому после перезагрузки N начинается с 0, а M меньше 225.
- 0 → 158 и есть продолжение:
  - к перезагрузке пришло 75 МБ = 4 целые части (67 108 864 байта) и половина пятой;
  - 224 893 347 − 67 108 864 = 157 784 483 байта ≈ 158 МБ — ровно столько скачано во второй раз;
  - половина пятой части потеряна — так задумано (modelFiles.ts: «a broken connection costs one part»).
- Судья исправлен: читает M из «N из M МБ» до и после. Сохранено = M до − M после ≥ скачанного до обрыва − одна часть (16,8 МБ).
- Прогон 2 — тот же сценарий с исправленным судьёй.

Что видно в консоли воркера (`sw-s-2-after-int7-05a0555-run2-console.log.txt`, распознанный текст вырезан):

- В момент перезагрузки воркер успел написать: «model … v3_e2e_ctc.int8.onnx from own, try 1, part 5 goes on from byte 8519680: TypeError: Load failed».
- Это путь 05a0555 (продолжить часть с байта): 4 × 16 777 216 + 8 519 680 = 75,6 МБ, то есть «76» на экране.
- Сам он умер вместе со страницей. Через перезагрузку переживают только целые части, поэтому 8,5 МБ пятой части скачаны заново.

## Чего прогон не доказывает

- Не iPhone и не приложение с экрана «Домой» (жалоба владельца — там). Хранилище на Mac WebKit ответило сразу (cache, запись части 30 мс); зависшего хранилища, из-за которого была вторая правка, здесь не было.
- Обрыв здесь — перезагрузка страницы. Обрыв сети посреди части (что чинит 05a0555, Range) этот сценарий не проверяет: части приходят целиком, со скоростью 2 МБ/с.
