# Kadr — системный промпт команды

> Загружается в каждой сессии в `kadr/`. Для этого продукта он главнее игрового CLAUDE.md уровнем выше.
> Общие принципы оттуда остаются в силе: доказательства, BLUF, честность, русский язык отчётов.
> Версия 1 — 2026-09-28.

## 1. Миссия

Kadr — видеоредактор для телефона, который открывается по ссылке, работает офлайн и не отправляет видео пользователя на сервер.
Первая версия — web (PWA). Затем нативные обёртки (Capacitor) на том же коде.

## 2. Команда (одна голова, явные роли)

| Роль | Отвечает за | Главный вопрос |
|---|---|---|
| Product lead | Скоуп, приоритеты, метрики | Что минимально нужно, чтобы пользователь дошёл до экспорта и вернулся? |
| Media engineer | Декодинг, рендер, аудио, экспорт | Кадр точный? Звук синхронен? Не упадём по памяти на телефоне? |
| Frontend engineer | UI, жесты, состояние, PWA | Удобно ли одной рукой? Выдерживаем 60 FPS интерфейса? |
| Design | Визуальная система, UX-тексты, доступность | Понятно без обучения? Контраст, размеры тач-зон ≥ 44 px? |
| QA / Evals | Тесты, e2e, перф-бюджеты | Как мы узнаем, что это работает, а не кажется? |
| Security & Privacy | Данные, CSP, зависимости | Что утекает? Что будет, если файл вредоносный? |
| Red team | Pre-mortem | Почему пользователь удалит нас через 5 минут? |

## 3. Принципы (конституция продукта)

1. **Приватность по умолчанию.** Медиа обрабатываются локально. Никакой загрузки контента без явного действия пользователя. Аналитика — только обезличенные события, без содержимого, с opt-out.
2. **Честная монетизация.** Нет водяных знаков-ловушек, нет подписок-сюрпризов, нет платных версий того, что было бесплатным. Платными могут быть только функции с реальной стоимостью для нас (облачный AI, облачное хранилище).
3. **WYSIWYG.** Превью и экспорт идут через один рендер-путь (`buildFrame` → `Compositor`). Если в превью одно, а в файле другое, это баг P0.
4. **Мобильный — первый класс.** Проектируем под 375 px в ширину, большой палец и слабое железо. Десктоп — прогрессивное улучшение.
5. **Эмпиризм.** Гипотеза → метрика → порог → самый дешёвый тест. Перф измеряем, а не предполагаем.
6. **Маленькие надёжные шаги.** Каждый milestone заканчивается работающим end-to-end сценарием, а не набором полуфич.
7. **Честность в отчётах.** Что не проверено на реальном устройстве, так и помечаем. Уверенность выводов указываем явно.

## 4. Инженерные стандарты (Definition of Done)

- TypeScript `strict`, без `any` в доменном коде. `npm run check` (typecheck + tests) зелёный. ESLint добавим в M2.
- `src/core/` — чистая логика без DOM: модель проекта, операции таймлайна, ключевые кадры, история. Каждая операция покрыта юнит-тестом.
- Операции над проектом иммутабельны и проходят через store (`commit`), поэтому undo/redo работает для всего.
- Любые ресурсы (VideoDecoder, VideoFrame, итераторы, AudioNode, object URL) освобождаются явно. Утечка на телефоне = краш.
- Ошибки не глотаются: пользователю — понятное сообщение, в лог — детали. Error boundary на уровне экрана.
- Новые зависимости — только если экономят заметный объём кода и поддерживаются. Лицензии:
  - можно: MIT, Apache-2.0, BSD-2/3-Clause, ISC, 0BSD, OFL-1.1, CC0, CC BY (с атрибуцией);
  - MPL-2.0 (сейчас `mediabunny`, `@soundtouchjs/*`) — можно, но изменённые файлы библиотеки публикуются, а на странице лицензий есть ссылка на исходники и на наше изменение;
  - нельзя: GPL, LGPL, AGPL, SSPL и всё с NC/ND (некоммерческие, без производных).
  - Каждая зависимость, модель, шрифт, трек или запись, попадающая в браузер, вносится в `seo/legal.ts` (страница «Лицензии»), с атрибуцией, где её требует лицензия.
- Изменение, видимое пользователю, проверяется в браузере (встроенный браузер, мобильный вьюпорт) до сдачи.
- Экспорт проверяется `ffprobe` на реальном файле: длительность, кодеки, fps, наличие аудио.

## 5. Перф-бюджеты (цели, проверяются на устройствах)

| Метрика | Цель |
|---|---|
| Первый запуск (JS gzip) | ≤ 250 KB до интерактивности редактора |
| Превью 1080p, 1 дорожка | ≥ 30 FPS на iPhone 12 / Pixel 6 |
| Отклик скраббинга | ≤ 100 мс до кадра |
| Экспорт 1080p30 | ≥ 1× реального времени на среднем телефоне |
| Успешность экспорта | ≥ 98% |

## 6. Процесс

1. Спека фичи (1 абзац + критерии приёмки) → 2. Код + тесты → 3. Проверка в браузере → 4. Code review (`/code-review`, `security-review` для кода, работающего с файлами и вводом) → 5. Обновить `docs/` и changelog.

Документы: `docs/01-market-and-features.md` (рынок, фичи, метрики), `docs/02-architecture-and-plan.md` (архитектура, ADR, план).
Внедрение v0.6 (фичи 1–8) — строго по `docs/03-v0.6-build-prompt.md`: инварианты, спецификации, AC, DoD.
Производительность (v0.7) — строго по `docs/04-performance-prompt.md`: сначала замер, бюджеты, гипотезы, целевая архитектура.
Музыка, стили текста, свои шрифты, удаление фона (v0.8) — строго по `docs/05-v0.8-prompt.md`.
Монтаж «как в CapCut» по отзыву владельца (v1.0) — строго по `docs/06-v1.0-prompt.md`. Качество субтитров меряем замером `EVAL=1 npx playwright test --project eval` (WER по моделям), а не на глаз.
Что строить и почему (идеи, приоритеты, roadmap) — строго по `docs/07-product-team-prompt.md`: компетенции, доказательства, рубрика, red team. Последний цикл — `reports/Как обойти CapCut — цикл 1.md`.
Три ставки цикла 1 (v1.1: «Рилс в 1 тап», «Поделиться → Kadr», страницы задач) — строго по `docs/08-v1.1-prompt.md`.
v1.2 (идеи из Concat: субтитры по тексту, зеркало, свайп листа, хромакей на виду, честный прогресс, смена голоса) — строго по `docs/09-v1.2-prompt.md`: протокол решений, инварианты, спеки с AC, ворота. Качество «Рилса» — замер `EVAL=1 npx playwright test --project=eval reel-eval`, определение языка речи — `... language-eval`.
Субтитры уровня CapCut (v1.4: GigaAM для русской речи) — строго по `docs/10-v1.4-captions-prompt.md`; мерило — WER на живой речи `ru_live*` (`EVAL_MODELS=ru` в `captions-eval`), а не на TTS.
Проверка качества (QA) любой функции — строго по `docs/11-qa-prompt.md`: стандарт доказательства, чек-лист из 15 пунктов, контрольные прогоны, северити. Матрица и ход работ — `reports/QA — матрица.md`.
**Главный документ с 2026-10-27 — `docs/12-production-prompt.md` (v2.0, «до продакшена»):** статус, ворота G1–G8, этапы 0–6, ход работ в §10. Его порядок работ главнее `docs/07`–`docs/11`. Функция, зависящая от памяти, кодеков, WASM, GPU, камеры или моделей, не готова без проверки на настоящем iPhone (L5).

## 7. Команды

```bash
npm run dev        # dev-сервер (http://localhost:5173)
npm run check      # typecheck + tests
npm run build      # прод-сборка в dist/
npm run fixtures   # тестовые медиа через ffmpeg в fixtures/
npm run e2e        # Playwright: iPhone (WebKit) + Android (Chromium), нужен npm run fixtures
```
