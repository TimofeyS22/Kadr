# Kadr: архитектура и план реализации

Дата: 2026-09-28.

## 1. Обзор

Локальное приложение без бэкенда: статическая PWA, вся обработка на устройстве.

```
UI (React)  ──commit()──►  Store (Zustand: project + history + UI state)
   │                              │  autosave (debounce)
   │                              ▼
   │                        Storage (IndexedDB: проекты JSON, медиа Blob, пики волн)
   ▼
Player / Exporter ── buildFrame(project, t) ──► FrameDesc (чистые данные)
   │                                              │
   ├─ MediaPool: Input на ассет (Mediabunny) ─────┤ кадры клипов (CanvasSink)
   ├─ TextRasterizer (2D canvas → текстура) ──────┤
   ▼                                              ▼
AudioEngine (Web Audio)               Compositor (WebGL2: трансформы, цвет, хромакей, переходы, фон)
   │                                              │
   └─ экспорт: OfflineAudioContext по окнам ──► Mediabunny Output (MP4: H.264 + AAC)
```

**Ключевое свойство — WYSIWYG.** Превью и экспорт вызывают одни и те же `buildFrame` и `Compositor`. Различается только источник времени (аудиоклок или счётчик кадров) и режим декодирования (допускаем пропуск кадров или ждём точный кадр).

## 3. Модель данных (кратко)

- `Project { settings { width, height, fps, background }, tracks[] }`. Дорожки идут снизу вверх (порядок композитинга). Дорожка `main` магнитная, её клипы упакованы встык с учётом перекрытий переходов.
- `Clip`: `start` и `duration` на таймлайне (с). У медиаклипов есть `in` (секунда источника) и `speed`, отсюда `srcTime = in + (t - start) * speed`.
- Анимируемые свойства: `{ v, k?: [{ t, v, e }] }`. Время ключей относительно клипа; интерполяция с easing.
- Переход хранится у клипа как `transitionIn { type, duration }` и перекрывает его с предыдущим клипом main-дорожки.
- Медиа хранится отдельно от проекта (`Asset` + Blob), проект ссылается на `assetId`. Снимок истории — лёгкий JSON.

## 4. ADR (решения)

| # | Решение | Альтернативы | Почему | Пересмотреть, если |
|---|---|---|---|---|
| 1 | PWA сначала, Capacitor потом | Нативный Swift/Kotlin, Flutter | Один код, дистрибуция ссылкой, агент собирает и проверяет из CLI | Web-перф не проходит G1 |
| 2 | WebCodecs через Mediabunny | ffmpeg.wasm | Аппаратное ускорение (в 10–50 раз быстрее wasm), нет 30 МБ wasm, работает на iOS 26 | Нужны экзотические кодеки: тогда ffmpeg.wasm как ленивый fallback |
| 3 | WebGL2-композитор | Canvas 2D, WebGPU | WebGL2 есть везде (iOS 15+). Шейдеры нужны для цвета, хромакея и переходов. `ctx.filter` в Canvas 2D поддерживается нестабильно. WebGPU есть не везде | WebGPU станет повсеместным (ускорение AI-эффектов) |
| 4 | IndexedDB для Blob медиа | OPFS | Работает во всех браузерах одинаково, Blob читается кусками | Упрёмся в экспорт больших файлов: тогда OPFS StreamTarget |
| 5 | Иммутабельный документ + снимки истории | Command pattern, CRDT | Проще и надёжнее. Документ маленький (килобайты), undo бесплатен для всех операций | Появится совместное редактирование: тогда CRDT (Yjs) |
| 6 | Экспорт в главном потоке (v0.1) | Worker + OffscreenCanvas | Быстрее реализовать, шрифты и текст проще. Цикл уступает event loop | UI заметно фризит при экспорте: переносим в worker (v0.2) |
| 7 | Без бэкенда | Облачный рендер | Приватность, стоимость $0, нет ПД → меньше юридических рисков | Облачный AI (v0.3+) |

## 5. Безопасность и приватность

- Никаких сетевых запросов с контентом. Шрифты вшиты в бандл (OFL), внешние CDN не используются. CSP: `default-src 'self'`.
- Вредоносные файлы разбирает парсер Mediabunny в песочнице браузера, декодирует браузер. На случай битых файлов стоят таймауты и try/catch на импорте.
- Лимиты: размер одного файла ≤ 4 ГБ (предупреждение с 1 ГБ), длительность проекта ≤ 30 мин (v0.1).

### Безопасность новых частей
- CSP расширяется точечно: `connect-src` для `huggingface.co`, `*.hf.co`, `cdn.jsdelivr.net` (модели и WASM ORT), `script-src 'wasm-unsafe-eval'` для WASM. Звук и видео пользователя никуда не отправляются, скачиваются только файлы модели.
- Перед первой загрузкой модели показываем размер и просим подтверждение.
- Импорт `.kadr` валидирует JSON (версия схемы, типы) и не исполняет ничего из архива.

4. Шумоподавление (RNNoise → производный ассет).
5. Автосубтитры (worker + UI загрузки модели + редактор + SRT).
6. Бэкап и восстановление `.kadr`.
7. Экспорт в OPFS, пресеты экспорта, безопасные зоны в превью.
8. Проверка каждого пункта в браузере, e2e экспорт + ffprobe, обновление документации.

**Проверки:** `npm run check` — 32/32 тестов. Прод-сборка: стартовый JS ≈ 85 KB gzip. AI-чанки ленивые и кэшируются при первом использовании (RNNoise 4,8 МБ, воркер ASR 0,5 МБ + WASM ORT 26,8 МБ, модели 41/77 МБ — с Hugging Face один раз).

**Решения по ходу:**
- Нейтральная графитовая палитра и плёночный янтарь вместо почти чёрного фона с красным акцентом (промпт плагина frontend-design).
- На телефоне превью ужимается над открытой шторкой.
- На iOS по умолчанию модель tiny.

**Известные ограничения v0.2:**
1. WASM ORT 26,8 МБ требует хостинга с файлами больше 25 МБ: GitHub Pages и Netlify подходят, Cloudflare Pages — нет.
2. ASR однопоточный: без cross-origin isolation многопоточность WASM недоступна.
3. Отменённое шумоподавление через undo оставляет файл в хранилище до удаления проекта.
4. Whisper «галлюцинирует» текст на музыке без речи. Нужен детектор речи (VAD) перед распознаванием (v0.3).
5. Скорость ≠ 1× по-прежнему меняет тон (SoundTouch — v0.3).

**Следующий шаг:** G1 на реальных устройствах (`npm run dev -- --host`): субтитры RU/EN на iPhone (tiny) и Android (base), войсовер, экспорт → «Фото». Затем v0.3 (Should-список отчёта).

### v0.8.2: жесты в превью (по отзыву владельца)

**Проблема.** После добавления текста попытка его сдвинуть двигала видео: слой выбирался по точному попаданию пальца, а при промахе мимо букв под пальцем оказывалось видео.

**Правило теперь** (как в CapCut, но прощающее промахи):
1. Касание выбранного слоя двигает его.
2. Касание другого «плавающего» слоя (текст, стикер, наложение) переключает на него и двигает его.
3. Касание в любом другом месте кадра двигает выбранный слой; щипок двумя пальцами где угодно масштабирует и вращает его.
4. Тап без движения по пустому месту или по видео завершает редактирование (снимает выделение).
5. Без выделения палец берёт то, что под ним, включая основное видео.

**Подсказки и проверка:**
- Новый текст и стикер выбраны сразу, поэтому их двигают с любого места.
- Одноразовая подсказка: «Тяните в любом месте кадра…».
- e2e: тяга с края кадра двигает текст, а не видео; тап по видео снимает выделение; следующая тяга двигает уже кадр.

### v1.1.1: язык речи определяется по самой речи (2026-10-16)

Закрывает риск из v1.1.0: при английском интерфейсе и русской речи Whisper *переводил* речь, а в «Рилсе в 1 тап» пользователь не видел выбор языка до запуска.

**Причина глубже, чем казалось.** В transformers.js у Whisper нет определения языка. Без `language` библиотека пишет в лог «defaulting to English» и распознаёт как английский. То есть пункт «Авто» в субтитрах с v0.2 на деле был «английский». Решение v1.0 «язык по умолчанию — язык интерфейса» обходило именно это.

**Что сделано:**
- Определение языка средствами самого Whisper (`asr.worker.ts`, `detectLanguage`): один шаг декодера после `<|startoftranscript|>`, затем самый вероятный языковой токен среди 11 языков Kadr. Язык определяется один раз по самому длинному куску речи и дальше используется для всех кусков, без скачков языка внутри ролика.
- «Авто» по умолчанию и в «Рилсе», и в «Автосубтитрах».
- В итоге «Рилса» — «Язык речи (Kadr определил сам)» со списком. Другой язык переделывает рилс с ним один раз, не меняя сохранённые настройки. Метрика `reel_language_changed` {from, to, detected} показывает долю ошибок определения в реальных роликах.
- В «Автосубтитрах» после «Авто» появляется подсказка «Язык речи: … Неверно? Выберите его и создайте заново».

**Замер** (`EVAL=1 npx playwright test --project=eval language-eval`, модель base, английский интерфейс, macOS TTS; новые образцы `lang_*.mp4` в `npm run fixtures`):

### v1.2.1: смена голоса и точная синхронизация звука с картинкой (2026-10-17)

Работа по `docs/09` (V1). Главное в этой версии — не смена голоса, а **системная ошибка синхронизации, найденная тестами V1**: с v0.5 звук во всех экспортах Kadr отставал от картинки.

**Синхронизация: замер до и после** (новый e2e: исходник `avsync.mp4` с белыми кадрами и писками ровно в 1,0 и 2,5 с, экспорт через Kadr, сдвиг звука относительно картинки):

| Экспорт | До | После |
|---|---|---|
| Chromium, обычный клип | +43 / +44 мс | **0 / −1 мс** |
| Chromium, обработанный звук | +87 / +88 мс | **0 / 0 мс** |
| WebKit, обычный клип | +42 / +58 мс | **0 / +14 мс** |
| WebKit, обработанный звук | +86 / +103 мс | **0 / +14 мс** |

**Причины (каждая доказана замером, а не догадкой):**
1. **Задержка AAC-кодера.** Кодер ставит перед звуком «priming», 2112 сэмплов ≈ 44 мс, а наши MP4 без edit list, поэтому плееры её проигрывают. Задержка была в каждом экспорте и в каждом производном звуке (шумоподавление, улучшение голоса, естественный голос на скорости, эффекты), причём каскад копил её: 44 × N мс. Решение — `engine/encoderDelay.ts`: задержка измеряется один раз на кодек (пачка тона кодируется и декодируется тем же `AudioBufferSink`, что и при воспроизведении), и столько сэмплов снимается перед кодированием — в экспорте (`MixStream`) и в производных звуках (`processAssetAudio`).
2. **RNNoise отвечает на два кадра позже**: +20 мс, подтверждено кросс-корреляцией огибающих речи. Компенсируется в `denoiseAsset`.
3. **SoundTouch** (естественный голос на скорости, «Бурундук», «Низкий») сдвигает звук в зависимости от высоты тона: на 1,6 — на 40 мс раньше, на 0,72 — ≈ 0. Сдвиг измеряется пачкой тона (совпадает с речью ±2 мс) и компенсируется в обе стороны. Попутно SoundTouch получил верную частоту дискретизации 48 кГц, он работал как с 44,1.

**Старые проекты:** версия синхронизации теперь входит в ключ обработанного звука (`~2`), а кэш производных звуков без отметки `sync: 2` не используется. При открытии такого проекта звук пересобирается один раз («Уточняем синхронизацию звука…»), без потери обработки.

**Остаток:** +14 мс на втором писке в WebKit был и до правки, разница между вспышками та же. Это меньше половины кадра при 30 fps; источник — метки времени видео в WebKit, а не звук.

**Смена голоса** (`core/voicefx.ts` + `engine/audiofx.ts`). Отдельный инструмент «Голос» у видео- и аудиоклипов, 10 пресетов:

- **с изменением высоты тона:** Бурундук, Низкий;
- **с фильтрами и искажением:** Робот, Телефон, Мегафон, Радио;
- **с эхом и реверберацией:** Эхо, Зал, Собор, Под водой.

Как устроено:
- Потоковый DSP без швов на 10-секундных окнах: полосовые фильтры, насыщение, кольцевая модуляция, задержка, реверберация в стиле Freeverb, вибрато.
- Высота тона — через SoundTouch; в конце лимитер −1 dBFS.
- Цепочка: очистка → голос → естественный голос на скорости. Голос входит в ключ звука, поэтому превью совпадает с экспортом.

**Найдено замером и исправлено:**
- насыщение стояло после полосы и заново заполняло верха — перенесено до полосы;
- телефонной полосе нужен срез 48 дБ/окт — сделан.

Метр в e2e тоже был мягким: фильтр 4-го порядка на 4 кГц показывал 18 дБ при реальных 30. Заменён на фильтр 8-го порядка на той же частоте.

### v1.3.1: субтитры не падают, если браузер отказывается декодировать звук (2026-10-18)

Ошибка владельца: «Не удалось создать субтитры: Unsupported configuration. Check isConfigSupported() prior to calling configure().»

- *Причина (уверенность высокая):* текст выдаёт Chromium (Chrome, Яндекс Браузер, Edge, Samsung Internet). Его `AudioDecoder.isConfigSupported()` не проверяет `description` дорожки, а `configure()` проверяет. Дорожка проходит `canDecode()` и падает на первом декодировании. Файл владельца не получен, точную конфигурацию не воспроизвести. Поэтому чиним класс ошибок, а не один файл.
- *Теперь* (`src/engine/sound.ts`):
  - `playableAudioTrack` — при импорте и открытии выбирается дорожка, у которой реально декодируется первый пакет: сначала включённые, потом стерео/моно, потом по порядку. Видео iPhone 16+ с 4-канальной пространственной дорожкой рядом со стерео AAC больше не теряют звук.
  - `ResilientSink` — звук декодируется WebCodecs; если браузер отказывает, остаток диапазона декодирует собственный медиастек браузера (`decodeAudioData`). Пакеты окнами по 10 с копируются без перекодирования в маленький MP4/WebM/Ogg/MP3/WAV, память ограничена. Через него идут превью, экспорт, субтитры, волна, реверс, замер задержки кодера.
  - Субтитры: файл, который не читается ни одним путём, пропускается, тост называет его по имени, остальное распознаётся. Если не читается ничего, ошибка называет файл, а не «Unsupported configuration». Экспорт в этом случае падает с понятным сообщением, а не молча теряет звук.
- *Попутно (баг v1.3.0, поймала регрессия):* «Настройки» и «Отмена» на экране прогресса не срабатывали, пока качалась модель или распознавался кусок. Обещание ждало ответа воркера и не слушало отмену. Теперь каждый запрос к воркеру отменяется сразу: загрузка модели докачивается в фоне и кэшируется, ответ отменённого запроса отбрасывается. Id запросов уникальны, поэтому старый ответ не попадёт в новый запуск.
- *Попутно:* в замер качества субтитров добавлена живая русская речь с телефонов (SOVA RuDevices, CC BY 4.0, `scripts/fetch-live-speech.mjs` → `eval_ru_live`, `eval_ru_live_music`). TTS слишком «чистый» для оценки.

**Тесты:**
- `npm run check` — 152 юнит-теста.
- Новые e2e (WebKit и Chromium, 8/8): видео «iPhone 16+» — экспорт со звуком стереодорожки; принудительный отказ WebCodecs (`configure` падает, `isConfigSupported` говорит «да»): субтитры с правильными словами и экспорт со звуком, рассинхрон 0–3 мс; файл, который не читает ни WebCodecs, ни `decodeAudioData`: субтитры без него и тост с его именем.

**Не проверено на устройстве:** у владельца (Chromium) — нужен его файл или повтор после обновления.
