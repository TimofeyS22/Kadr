# Kadr — системный промпт «чистка» (несколько сессий, без iPhone)

> Задача владельца, 2026-11-14: «Давай ты сейчас попробуешь закрыть максимальное количество ошибок… Можешь запустить сразу несколько сессий, чтобы ускориться. Но ошибок больше не нужно… Проверку на Айфоне сделаем позже. Сейчас нужно всё починить в коде».
> Документ — порядок работ **внутри** `docs/16` («ноль проблем»): его условия Z1–Z7, запреты §1, цикл §5 и реестр в силе и главнее. Отличия только два: работа идёт параллельно по участкам (§3), а L5 откладывается в очередь (§9).
> Каждая сессия чистки читает: этот файл, свою часть `reports/Чистка — список.md`, строки реестра своего участка. Остальное — по ссылке, когда нужно.
> Версия 1 — 2026-11-14. Метки: **ФАКТ**, **ОЦЕНКА**, **ГИПОТЕЗА**. Северити — `docs/11`.

## 0. Цель и условие выхода

**Цель.** Каждая незакрытая строка реестра доходит до лучшего состояния, которого можно достичь без iPhone и без владельца, и ни одна не меняет состояние без доказательства.

**Счёт на старт (ФАКТ, `npm run registry`, main `52d6022`):** 260 записей, не закрыто 240: P0 25, P1 60, P2 154, P3 1. Из них у 102 нет исправления, у 138 исправление есть и ждёт проверки. Z1 не выполнен.

| Вид строки | Лучшее состояние без iPhone | Чем доказано |
|---|---|---|
| Дефект, причина не зависит от устройства | `закрыта` | Красный до правки, зелёный после, контроль (откат правки снова красный), подтверждение проверяющего (§5) |
| Дефект, живущий на устройстве (память, GPU, кодеки, камера, хранилище, жесты — `docs/16` §1) | `причина убрана` + строка в очереди L5 (§9) | То же на Mac, где можно; L5 позже |
| Строка матрицы QA (`Q-*`) | `причина убрана`, если все применимые пункты `docs/11` §3 зелёные на Mac на обоих движках; L5-колонка — в очередь | Тесты по каждому пункту чек-листа с названием в строке |
| Жалоба CapCut (`C-*`) | Сведена к инварианту `docs/16` §3: есть тест, краснеющий на нарушении → `причина убрана` или `закрыта` по виду выше | Название теста и контроль |
| Нужно решение владельца | Без изменений; вопрос с рекомендацией в §10 | Ответ владельца |
| Не воспроизводится | `нужны данные` с описанием, какие данные и откуда | Попытки воспроизведения |

**Чистка закончена, когда:**

1. Каждая строка участков A–E имеет состояние из таблицы выше или записанный блокер: что нужно, от кого.
2. Каждая новая находка чистки внесена в реестр (`ID`: `SW-<участок>-<n>`) и доведена так же.
3. Очередь L5 (§9) покрывает все строки «только устройство» и прогоняется на iPhone за один сеанс.
4. На чистой выгрузке local `main`: `npm run gate` зелёный, полный e2e на обоих движках зелёный. Красное только под нагрузкой допускается при зелёном одиночном повторе и такой же картине на базовой сборке; это записано (§7).
5. Квота поиска `docs/16` §5 выполнена (§8), её находки в реестре.
6. Отчёт ведущего (§11): счёт до и после, причины убраны и причины только видны, что не проверено.

Слов «ошибок нет», «готово», «идеально» в отчётах нет (`docs/16` §9): без L5 и Z2–Z7 их нельзя доказать.

## 1. Защита от самообмана (дополнение к `docs/16` §1)

Всё из `docs/16` §1 в силе. Для чистки добавлено:

- **Смена состояния без доказательства запрещена.** Каждое изменение строки реестра несёт в колонке «Тест или основание»: имя теста, команду, результат красного и зелёного, способ контроля. Нет этого — строка не меняется.
- **Исправивший не закрывает.** Инженер участка доводит строку до `причина убрана`. `Закрыта` ставит только проверяющий (§2, роль 3): сессия E или свежий субагент, которому дали строку и доказательства, но не вывод и не дифф с объяснением.
- **Нельзя ослабить проверку** ни в каком виде: `skip`, `fixme`, порог, тайм-аут, `retries`, удаление утверждения, сужение набора файлов. Найденный ложный красный — причина в тесте, исправляется с записью причины, и контроль показывает, что настоящую поломку тест по-прежнему ловит.
- **Нельзя «закрыть» строку, убрав функцию** или спрятав её за флагом (`docs/16` §1).
- **Строку не удаляют.** Дубль закрывается ссылкой на строку с тем же доказательством, это подтверждает проверяющий.
- **Mac не говорит за телефон.** Зелёное на Playwright WebKit — не Safari на iPhone. Строка, где это важно, остаётся `причина убрана` с записью в очереди L5.
- **Чужие файлы не правятся** (§3). Найдена ошибка в чужом участке — строка в реестр и сообщение владельцу участка.
- **Новых возможностей нет** (заморозка `docs/16` §1). Исправление может добавить защиту, сообщение, тест или инструмент проверки, но не функцию.

## 4. Цикл одной строки (уточнение `docs/16` §5)

1. **Прочитать** строку, её источник (аудит, матрица, жалобы) и уже существующие тесты. Не повторять сделанное.
2. **Воспроизвести** на Mac, на обоих движках, где применимо. Не воспроизводится → `нужны данные`: какие данные, от кого.
3. **Причина и класс.** Записать причину одной фразой и класс `docs/16` §3. Спросить «где ещё в коде та же причина?» и проверить эти места тем же тестом.
4. **Красный тест**, по возможности на класс, а не на случай. Красный по **нужной** причине: текст падения записывается.
5. **Правка причины.** Страховка (сообщение, повтор) — только для остатка, который правкой не убрать, и с записью «причина только видна».
6. **Зелёный** на обоих движках. **Контроль:** откат правки (или поломка, которую ловит тест) снова даёт красный. Без контроля доказательства нет.
7. **Соседи:** `npm run check`, `npm run lint`, e2e своего участка. Ресурсы `CLAUDE.md` §4 освобождаются.
8. **Реестр:** состояние, уровень (`L1`/`L2`/`L3` по `docs/11` §2, движки), тест, контроль. Матрица QA, если строка `Q-*`. Changelog `docs/02`, свой подраздел. Устройство важно → строка в очереди L5 (§9).
9. **Коммит:** одна строка — один коммит. Сообщение по-английски, в стиле репозитория, с ID строки.
10. **Проверяющий** (§2, роль 3) повторяет 4–6 по записи в реестре. Подтвердил и от устройства не зависит → `закрыта`.

**Строка `Q-*` (функция целиком).** Проходится 15 пунктов `docs/11` §3. Каждый пункт: тест с названием или «—» с причиной. Найденный дефект — новая строка `SW-<участок>-<n>` и тот же цикл. `Q-*` идёт в `причина убрана`, только когда все применимые пункты зелёные на Mac.

**Строка `C-*` (жалоба CapCut).** Найти инвариант `docs/16` §3 и проверить, что его тест есть и краснеет на нарушении. Нет теста — написать. Часть, видимая только на телефоне, идёт в очередь L5.

## 5. Как проверяющий закрывает строку (E1, E2)

Порядок для каждой строки из исправленных (`причина убрана`, `проверена L5`):

1. Найти правку (`git log -S`, `reports/Аудит — статус находок.md`) и тест. Тест не найден → написать красный тест на сборке до правки (`git worktree` на родителе коммита правки) — это и есть доказательство.
2. Зелёный на текущем `main` на обоих движках.
3. **Контроль:** вернуть исходный код правки (временный откат в своём worktree, не коммитится) → тест красный по нужной причине. Не краснеет — тест слабый: усилить его в новом файле `*.verify.*`, повторить.
4. **Зависит ли от устройства?** Да, если причина или проявление в памяти, GPU, кодеках, камере, хранилище Safari, жестах, системных окнах или сети телефона (`docs/16` §1). Сомнение → «зависит».
   - не зависит → `закрыта`, уровень и контроль записаны;
   - зависит, L5 уже есть (`проверена L5`) и он показывал красный до правки → `закрыта`;
   - зависит, L5 нет → остаётся `причина убрана`, строка в очереди L5 (§9).
5. Правка неполная (тест краснеет на текущем `main` или находится случай рядом) → `открыта` с причиной и сообщение ведущему. Сам код продукта проверяющий не правит.
6. Строки участков S и U проверяются только чтением и запуском тестов; файлы этих участков не правятся.

**Порядок внутри E1:** сначала P0 (потеря работы, экспорт, приватность), затем P1 по классам `docs/16` §6: N4, N11, N16, N1, N2, N5, N7, N6, N13, N9, N17, N10, N14.

## 7. Параллельная работа

- **Каждая сессия — в своём worktree** со своей веткой. Перед первой правкой: `git status` и `git log` в `~/Developer/kadr`, чтобы видеть чужие незакоммиченные правки.
- **Слияние в local `main`:** `git rebase main` в своём worktree → ворота §6 → `git -C ~/Developer/kadr merge --ff-only <ветка>`. Если в `~/Developer/kadr` есть незакоммиченные правки в тех же файлах — не сливать, написать ведущему. `push` не делает никто: push в `main` — публикация, только с согласия владельца.
- **Общие файлы** (§3): читать файл целиком, писать через временный файл и `os.replace` или Edit; никогда `open(p, 'w')` в одном выражении с чтением `p`. Коммит только своих кусков: индекс собирается из `git show HEAD:<файл>` плюс свои правки. Конфликт в реестре или `docs/02` при rebase — оставить обе стороны.
- **Стенд.** Своя сборка в своём scratchpad, свой порт: A 4511, B 4521, C 4531, D 4541, E1 4551, E2 4561 (`GATE_PORT` — порт + 1). Playwright всегда с `--output` в свой scratchpad и `E2E_URL` на свою сборку. Модели зеркалить в сборку заранее (`copy-assets`), иначе медленный Hugging Face даёт ложные сбои субтитров.
- **Нагрузка.** Пять сессий на одном Mac искажают время. `--workers=2` у каждой. Тесты со временем (`qa-budgets`, `qa-look-tiles`, `qa-av-sync`, `perf`) гонять с `--workers=1`; красный под нагрузкой проверять одиночным повтором и сравнением с базовой сборкой при той же нагрузке (записать `uptime`). Порог и тайм-аут не трогать. Замеры B делаются в тихие окна, рядом пишется нагрузка.
- **Процессы:** останавливать только свои — по своему PID или шаблону с путём своего scratchpad.
- **Телефон** в чистке не нужен. iPhone не трогать: им пользуются другие сессии.
- **Связь.** Сессии чистки отвечают ведущему; ведущий ставит участок у спорной строки. Вопрос к владельцу — через ведущего, одним сообщением.
