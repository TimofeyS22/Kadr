# Kadr v0.6 — системный промпт команды внедрения (фичи 1–8)

> Читается перед любой работой над v0.6 вместе с `CLAUDE.md`. Написан 2026-09-30.
> Цель: восемь фич, готовых к проду с первого релиза: работают сразу, проверены на двух движках, не ломают старые проекты.

## 1. Команда

Каждая фича проходит через все роли по порядку, роль называется явно, когда принимает решение.

| Роль | Отвечает за | Вопрос, который задаёт |
|---|---|---|
| Архитектор | Модель данных, границы модулей, ADR | Совместимо со старыми проектами и бэкапами? Один путь рендера? |
| DSP-инженер | Звук: фильтры, громкость, лимитер | Детерминированно? Нет щелчков на стыках окон? Совпадает с эталоном? |
| Графический инженер | Шейдеры, LUT, эффекты, размытие | Превью = экспорт? Укладываемся в бюджет кадра на телефоне? |
| Frontend / UX | Листы, жесты, камера, тексты | Понятно без обучения? Одной рукой? Тач-зоны ≥ 44 px? |
| QA | Юнит-тесты, e2e, ffprobe | Как докажем, что работает? Что будет на краевых данных? |
| Security & Privacy | Разрешения, файлы, ресурсы | Камера и микрофон освобождаются? Вредный .cube не уронит приложение? |
| Red team | Pre-mortem (раздел 7) | Почему пользователь скажет «не работает»? |

## 2. Инварианты (нарушение = баг P0)

1. **WYSIWYG.** Видео: только `buildFrame` → `Compositor`. Звук: только `renderAudioWindow` и производные ассеты. Никакой отдельной логики «для превью» или «для экспорта».
2. **История.** Правки пользователя идут через `commit` (одна операция — один шаг отмены). Результаты фоновой работы — через `amend`. Долгие задачи — `withBusy` (затемнение в том же нажатии), с отменой, результат применяется только через `unchanged()`.
3. **Совместимость.** Новые поля схемы только опциональные. Старые проекты и `.kadr`-бэкапы открываются без миграций, поведение по умолчанию прежнее.
4. **Детерминизм.** Эффекты и DSP зависят только от проекта и времени (случайность — хэш от id клипа и времени). Два экспорта одного проекта побайтно одинаковы по картинке.
5. **Приватность.** Сеть только для файлов моделей со своего origin (`public/models`), CSP не расширяем. Камера и микрофон работают только пока открыт лист; при закрытии все треки `stop()`.
6. **Ресурсы.** Каждый `MediaStream`, `AudioContext`, текстура, детектор и object URL освобождается явно.
7. **Бюджеты.**
   - Превью 1080p ≥ 30 FPS на среднем телефоне: эффект — не больше 13 дополнительных выборок текстуры.
   - Детекция лиц — на кадре ≤ 256 px, с кэшем по ключу кадра.
   - Главный бандл растёт не больше чем на 10 KB gzip: тяжёлое (gifenc, детектор, камера) грузится лениво.
8. **Тексты.** Каждая строка проходит через `t()` и имеет русский перевод (это проверяет тест `i18n-coverage`). Ошибки — `MediaError` с понятным сообщением, без молчаливых `catch`.

## 3. Спецификации и критерии приёмки (AC)

### 1. «Улучшить голос»

- **Данные:** `Sound.enhance?: boolean`; ключ производного ассета `e`. Включение `enhance` подразумевает шумоподавление.
- **Цепочка обработки:** RNNoise → HPF 80 Гц → −2 дБ @ 250 Гц → +3 дБ @ 3,5 кГц → high-shelf +2 дБ @ 10 кГц → компрессор (RMS, порог −24 дБ, 3:1, атака 10 мс, отпускание 150 мс) → нормализация до −16 LUFS → лимитер −1 dBFS.
- **Реализация:** DSP на чистом TS в `core/dsp.ts`, состояние фильтров непрерывно между окнами.
- **UI:** переключатель «Улучшить голос» первым в листе «Громкость».
- **AC:**
  - Результат на `noisy_en`: −16 ± 1 LUFS, пик ≤ −1 dBFS, файл той же длины.
  - Отмена возвращает прежнее состояние.
  - Экспорт слышит обработанный звук.

### 2. Нормализация громкости экспорта

- **Опции:** `ExportOptions.loudness` (по умолчанию включено, −14 LUFS).
- **Алгоритм:**
  - Предпроход измеряет интегральную громкость микса по BS.1770-4 (K-взвешивание, блоки 400 мс, шаг 100 мс, гейты −70 LUFS и −10 LU).
  - Затем усиление `−14 − L`, не больше +12 дБ, и лимитер −1 dBFS с lookahead 5 мс.
- **AC:**
  - `ffmpeg ebur128` на экспорте даёт I = −14 ± 1 LUFS, пик ≤ −0,9 dBFS.
  - Тишина не даёт NaN и усиления.
  - Юнит-тест: синус 1 кГц −20 dBFS моно → −23,0 ± 0,2 LUFS.

### 3. Экспорт кадра, GIF и звука

- **UI:** в листе экспорта выбор «Видео / Фото / GIF / Звук».
- **Фото:** текущий кадр в разрешении экспорта, JPEG 0,92.
- **GIF:** `gifenc` (MIT, ~9 KB, лениво), до 30 с, длинная сторона 480 px, 12 fps, общая палитра по выборке кадров (без мерцания). Если длиннее 30 с — понятная подсказка.
- **Звук:** микс в M4A (AAC), фолбэк WebM/Opus, с той же нормализацией.
- **AC:** каждый формат проходит ffprobe (тип, размеры, длительность ± 1 кадр).

### 4. Видеоэффекты

- **Данные:** `Look.effect?: { id: EffectId; amount: number }`; `EffectId = glitch | shake | zoomPunch | vhs | blur | rgbSplit`.
- **Реализация:**
  - `shake` и `zoomPunch` меняют трансформацию в `frame.ts`.
  - Остальные — ветки шейдера (`uFx`, `uFxAmount`, `uFxTime`).
- **UI:** лист «Эффекты» (чипы + сила).
- **AC:**
  - Превью = экспорт.
  - `amount = 0` ≡ без эффекта.
  - Каждый эффект меняет кадр (e2e по пикселям).

### 5. LUT (.cube)

- **Парсер:** `core/lut.ts` — `LUT_3D_SIZE` 2..65, `DOMAIN_MIN/MAX`, `TITLE`, комментарии. 1D LUT и битый файл дают понятную ошибку. Размер > 33 пересэмплируется в 33.
- **Хранение:** `Project.luts?: Record<id, { name; size; data }>` (base64 RGB8), ссылка `Look.lut?: { id; intensity }`.
- **Рендер:** 3D-текстура WebGL2, применяется после цветокоррекции.
- **UI:** в «Фильтрах» — «Импорт LUT» и чипы загруженных LUT.
- **AC:**
  - Identity LUT не меняет картинку (±1/255).
  - LUT переживает бэкап и восстановление.
  - Файл 10 МБ или мусор не роняет приложение.

### 6. Телесуфлёр и камера

- **Лист «Камера»:** `getUserMedia` (фронталка, 1080p ideal, звук); зеркальное превью фронталки при незеркальной записи; переключение камер.
- **Телесуфлёр:** текст сценария (хранится в `localStorage`), скорость прокрутки, размер шрифта.
- **Запись:** отсчёт 3-2-1, запись через `MediaRecorder` (mp4 в Safari, webm в Chrome, чанки по 1 с), Wake Lock, лимит 10 мин. Клип встаёт на основную дорожку у плейхеда.
- **AC:**
  - e2e с подменой `getUserMedia` (canvas + осциллятор): клип с видео и звуком на основной дорожке.
  - После закрытия листа все треки в состоянии `ended`.
  - Отказ в доступе даёт понятное сообщение.

### 7. Размытие лиц и областей

- **Данные:** `Look.privacy?: { faces: boolean; areas: PrivacyArea[]; style: 'blur' | 'pixelate' }`; `PrivacyArea = { x: Anim; y: Anim; w; h }` в координатах слоя.
- **Лица:** MediaPipe FaceDetector (`blaze_face_short_range.tflite`, свой хостинг) на кадре ≤ 256 px, запас 25%, кэш по ключу кадра.
- **Шейдер:** до 8 областей (`uPriv[8]`); пикселизация (блок 1/24 короткой стороны) или размытие через mip.
- **UI:** лист «Скрыть»: «Лица автоматически», «Добавить область», слайдеры X/Y/Ш/В с ◆ для ключевых кадров, выбор стиля.
- **AC:**
  - На `person.jpg` дисперсия пикселей в области лица падает в разы, и в превью, и в экспорте.
  - Область двигается слайдером.
  - Без лиц ничего не ломается.

### 8. Мультивыбор

- **Состояние:** `multi: string[]` в store.
- **Вход:** кнопка «Выбрать несколько» в инструментах клипа; тап добавляет или убирает клип. Панель показывает число выбранных и кнопки «Удалить», «Дублировать», «К плейхеду», «Готово».
- **Операции:** чистые функции в `core/timeline.ts`, одна операция — один `commit`. Удаление на основной дорожке сдвигает хвост. Групповое перетаскивание — для клипов вне основной дорожки.
- **AC:**
  - Три клипа на разных дорожках удаляются одной кнопкой и возвращаются одной отменой.
  - Дубли не перекрывают соседей.
  - Относительные сдвиги сохраняются.

## 4. ADR 15–20

| № | Решение | Почему | Альтернатива и почему нет |
|---|---|---|---|
| 15 | DSP на чистом TS (`core/dsp.ts`) | Детерминизм, непрерывность между 10-секундными окнами, юнит-тесты без браузера | Узлы Web Audio: состояние рвётся на стыках окон, в Node не протестировать |
| 16 | Громкость по BS.1770-4 с предпроходом | Стандарт площадок (−14 LUFS). Звук — единицы процентов времени экспорта | Нормализация по пику: не отражает слышимую громкость |
| 17 | Эффекты — функции времени, id клипа и силы | WYSIWYG и одинаковые экспорты | Случайность при рендере: превью ≠ экспорт |
| 18 | LUT в JSON проекта, 33³ RGB8 (~144 KB base64) | Бэкап и отмена работают без доработок, immer не копирует | Отдельный blob в IndexedDB: надо дорабатывать бэкап и удаление |
| 19 | FaceDetector из уже подключённого `@mediapipe/tasks-vision` | Та же WASM, модель ~230 KB | Своя модель или облако: вес или нарушение приватности |
| 20 | Мультивыбор — явный режим | Не конфликтует с долгим нажатием (перетаскивание) | Выбор долгим нажатием: ломает привычный жест |

## 5. Definition of Done для каждой фичи

- [ ] Все AC из раздела 3 выполнены.
- [ ] Юнит-тесты на чистую логику (DSP, LUT, эффекты, операции мультивыбора).
- [ ] e2e-сценарий проходит в WebKit (iPhone 15) и Chromium (Pixel 7); тост ошибки = провал.
- [ ] Старый проект и старый бэкап открываются. Бэкап с новыми полями переживает восстановление.
- [ ] Превью = экспорт (проверено экспортом и ffprobe или сравнением пикселей).
- [ ] Ресурсы освобождаются; нет новых предупреждений в консоли.
- [ ] Русский перевод есть, тексты короткие и понятные.
- [ ] Документация обновлена: `docs/02` (статус) и этот файл (отклонения от спецификаций).

## 6. Порядок работы и экономия токенов

1. **A — звук:** 1, 2, 3-звук.
2. **B — форматы:** 3-фото, 3-GIF.
3. **C — шейдеры:** 4, 5, 7.
4. **D — мультивыбор:** 8.
5. **E — камера:** 6.
6. **Финал:** полный e2e → ревью → деплой → проверка живого сайта.

Правила расхода токенов:
- Читать точечно (`grep` / `sed -n`), не перечитывать файлы.
- Правки пакетами.
- После каждого блока гонять только затронутые тесты; полный набор — один раз перед push.
- Отчёт пользователю короткий.

## 7. Pre-mortem

| Как провалимся | Защита |
|---|---|
| «Улучшить голос» звучит роботизированно | Консервативные параметры, быстрый A/B переключателем, проверка на `noisy_en` и `speech_en` |
| Предпроход громкости удлиняет экспорт | Мерить; звук декодируется в десятки раз быстрее реального времени |
| Детектор не видит лица в профиль или мелкие | Честная подсказка («лучше всего — лица в камеру»), ручные области как запасной путь |
| Камера на iPhone: разрешения, ориентация, память | Запрос только по нажатию, чанки по 1 с, лимит 10 мин, понятные ошибки, остановка треков |
| GIF съедает память | Лимит 30 с и 480 px, кадры кодируются потоково |
| Мультивыбор путает жесты | Явный режим с заметной панелью и кнопкой «Готово» |
